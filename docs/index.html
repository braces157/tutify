Download Tuitify ↗
Windows x64Spotify Premium for playbackWhat’s new in v0.3.1 ↗

Download the v0.3.1 Windows x64 executable. No Rust toolchain is needed. Spotify playback requires Premium and a working audio output; the native demo does not.

Download tuitify.exe (v0.3.1) Download .ZIP package (v0.3.1)

Extract the ZIP and run .\scripts\install.ps1 to install for your Windows user and add Tuitify to PATH. Open a new terminal, then run tuitify anywhere.

Build the same v0.3.1 release with current stable Rust, the MSVC C++ build tools, and the Windows SDK:

cargo install --locked --git https://github.com/braces157/tutify.git --tag v0.3.1

Uses the v0.3.1 tag and its locked dependencies.

In Windows Terminal, open the folder where you want to keep the player. This downloads v0.3.1 into that current folder and starts guided Spotify sign-in:

iwr -useb https://github.com/braces157/tutify/releases/download/v0.3.1/tuitify.exe -OutFile tuitify.exe -ErrorAction Stop; .\tuitify.exe

Run tuitify demo for the native TUI with isolated fictional data and simulated playback. A normal first run opens two Spotify authorizations; use the same account in both. Later launches restore the queue paused. The browser demo above is a separate, silent simulation.

Before the first play

A few things
to know.

Do I need Spotify Premium?

Yes, for streaming. You can try the browser simulation or run the native demo without a Spotify account or audio device.

Does Spotify Desktop need to be open?

No. Tuitify streams and plays audio directly. Windows media keys work while you’re doing something else.

How does sign-in work?

You sign in through Spotify in your browser, using the same account for both authorization steps. Tuitify never sees your password. Tokens stay in Windows Credential Manager.

Where does my data go?

Preferences, queues, and listening totals stay on your PC. There’s no analytics collection. Discord presence is enabled by default and shares song details with your local Discord client. Read about data and privacy ↗
