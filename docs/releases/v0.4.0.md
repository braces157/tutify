# Tuitify v0.4.0

This release adds everyday queue controls, safer saved-state recovery, and
diagnostics that explain catalog restrictions while preserving useful results.

## Changes

- Filter the Queue by title, artist, or album while retaining original queue
  positions, duplicate occurrences, shuffle order, and undo behavior.
- Open F6 Listening Tools for 15/30/45/60-minute sleep timers, stop after the
  current track, and undoable cleanup of played, duplicate, or unavailable tracks.
- Use Ctrl+Enter for Play Next, Up/Down for recent-search recall, and Ctrl+R to
  recover a cleared queue filter.
- Distinguish expired authentication, restricted access, missing items, temporary
  rate limits, exhausted quota, outages, and invalid provider responses. Catalog
  retries retain service waits and avoid repeated requests to denied resources.
- Retain partial saved-library results and explain skipped sources with F4.
  Artist lists identify Top Tracks, verified Artist Search, or fictional Demo
  Tracks. F5 rechecks access without changing the provenance of retained rows.
- Keep stable Web API identity, legacy IDs, and streaming usernames separate.
  Reject mismatched or ambiguous account replacements while preserving local data.
- Create credential-free saved-state backups and preview whole-state restores.
  Inspect, back up, reset, or restore individual state files with confirmation
  tied to the preview. Preserve damaged and unsupported files and recover
  interrupted restore transactions under the instance lock.
- Run offline `doctor` checks or preview a redacted JSON `support` report.
  F7 displays classified session errors and the report preview. Exports create
  new files outside the live data directory and never upload automatically.
- Use `tuitify version --json` for embedded source/compiler identity and the
  observed executable hash. ZIP payload and external asset manifests record
  SHA-256 hashes; packaging rejects stale source builds and missing local links.
- Declare Rust 1.88 as the minimum and check it separately from stable formatting,
  tests, and strict Clippy in Windows x64 CI.

## Verification and scope

Automated checks and release evidence are recorded in
[VALIDATION.md](https://github.com/braces157/tutify/blob/v0.4.0/VALIDATION.md).
Live Spotify playback, account migration, and physical audio-device acceptance
were not repeated for this release. Offline and mock-provider tests do not prove
that a particular account has access to a restricted Spotify endpoint.

This release covers completed work from the first feature batch. The wider
roadmap, including installer rollback hardening, remains in progress.

## Install and upgrade

Download `tuitify.exe` or `Tuitify-0.4.0-windows-x86_64.zip`. Both have SHA-256
sidecars; `Tuitify-0.4.0-windows-x86_64.manifest.json` describes the release assets.
The ZIP includes documentation, release notes, and `scripts/install.ps1`.
Run the installer to place the executable on your user PATH.

Quit and reopen Tuitify after upgrading. A process already playing music keeps
its old code until restarted. Use a fresh search or Radio session to exercise
new discovery behavior; restoring a queue retains its existing tracks.

Windows 10/11 x64 and Spotify Premium are required for playback. The native
`tuitify demo` requires no Spotify account or audio device. Source builds require
Rust 1.88 or newer, MSVC C++ build tools, and the Windows SDK.
