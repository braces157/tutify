# Tuitify v0.7.0

Discover songs through Deezer's public catalog and keep listening as related
tracks refill the queue. Deezer supplies song, album, artist and radio metadata;
Volta, Spotify or YouTube supplies the full audio recording.

- Search, album browsing, artist tracks, Track Radio and Smart Shuffle use Deezer
  metadata while queue entries retain their catalog identities.
- Automatic queue continuation prepares related tracks near the end of the
  queue. Pausing, stopping, repeat settings and sleep timers take precedence.
- Volta prepares the next recording and a small decoded buffer before transition.
  If unavailable, matching YouTube audio is tried; combined Spotify + Volta can
  then use an existing Spotify Premium streaming connection.
- Native output negotiation retains available source resolution and uses a
  bandlimited converter when the device requires a different sample rate.
- Wide windows use a sidebar; tall windows keep Now Playing and the spectrum
  beside the queue. Queue counts, filtering and mouse controls follow the layout.
- Playback badges identify the audio provider alongside reported stream quality.
  Holding Space toggles once, and Windows media controls handle transport commands.

Plain `tuitify` prefers connected Volta with FFmpeg, then Spotify Premium, then
free YouTube Music. Explicit `--source youtube` selects YouTube even when Volta
is connected. Volta requests the highest available lossless stream, but the
returned recording may be lossy. The source-quality badge does not establish
bit-perfect Windows output. Restored queues start paused.

See [setup and controls](https://github.com/braces157/tutify/blob/v0.7.0/README.md),
[Volta setup](https://github.com/braces157/tutify/blob/v0.7.0/docs/volta.md), and
[validation](https://github.com/braces157/tutify/blob/v0.7.0/VALIDATION.md).

Download `tuitify.exe` or `Tuitify-0.7.0-windows-x86_64.zip`. SHA-256 sidecars and
`Tuitify-0.7.0-windows-x86_64.manifest.json` identify the published assets.
